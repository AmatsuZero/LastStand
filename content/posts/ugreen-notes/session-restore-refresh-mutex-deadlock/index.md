## 现象

真机 UI 测试注入占位会话后，应用一直停在启动页。隐私前置和应用初始化已完成，认证状态仍停在恢复中。
业务请求返回会话失效，随后刷新请求也返回刷新令牌失效。

## 已验证成因

恢复流程持有认证回调的 Mutex，并等待登录任务结束；登录任务中的业务请求等待刷新结果。
刷新失败路径清空会话后，同步调用登出任务，而登出任务需要同一把 Mutex。
登录等待刷新，刷新等待登录持有的锁，形成等待环。

Kotlin 协程 Mutex 不可重入。仅在应用存储写入占位 token 并不是完整的网络 mock；
真实请求仍会进入失效与刷新流程。检查隐私或启动路由无法解决这条等待环。

## 有效恢复

刷新令牌明确失效时，立即清空会话并返回失败；在认证模块独立 scope 中排队执行登出清理。
排队任务取得回调锁后再次检查会话仍为空，避免过期任务登出后来替换的新会话。
暂时网络错误不清空会话。

无凭据 UI 烟测另外使用仅测试构建导出的本地会话入口，并在共享网络的 transport 前拦截业务请求、使其快速失败。
生产页面和会话恢复继续运行，仓库加载失败后展示空主页。

## 边界

认证修复和测试网络边界分别验证。真实账号登录、真实硬件和完整离线能力不由空主页烟测证明。
原生 SDK 与显式绕过共享拦截器的请求不在本地网络边界内。
设备自动化初始化超时发生在任何 XCTest 用例执行前，不能算作启动断言失败，也不能算测试通过。

## 证据

- 组合回归在修复前明确检测到刷新仍等待登录回调的锁；修复后恢复结束并执行清理。
- 三条回归覆盖锁等待、排队清理期间替换会话、暂时刷新错误。
- 认证模块 host suite：22 tests，0 failures/errors/skips。
- 测试模块网络边界：1 test 通过；App 与 UI runner 的签名构建通过。
- 真机新入口日志显示认证完成并导航主页，用户目视确认进入主页。
- 后续重试成功初始化 XCTest，本地会话到主页断言通过：1 test，0 failures/skips。
  此前初始化超时的恢复原因尚未隔离，不能仅凭成功重试认定某个设置或参数就是根因。
- 静态分析存在存量问题，未宣称全量通过；真实账号与定时 CI 稳定性尚未验收。
