## 调研与验证口径

- 源码范围以 Android 主工程实际 Gradle module、source set、Git submodule 和生效的 Composite Build 映射为准；同时记录 Shared 的 Android 相关边界。RN 独立源码仓库和其他平台不自动纳入全仓审计。
- Shared 接入现状：主工程 `gradle.properties:28-29` 显式配置 `ugreenHomeSharedPath=../UgreenHome-Shared` 并启用 Composite Build，但该平级目录当前不存在。Shared 并非 Android 仓库的 Git 子模块；不能将路径声明当作已存在的 checkout。
- 用户指定的对象来源：`/Users/daubert/UGreen/ugreenhome/ugreenhome-shared`，即 iOS 仓库的 Shared Git 对象库。其原工作树仍为 `feature/samzhjiang/explore` / `96785f44747753468fc18a8b07405f695cbfbebb`，不得当作 Android 配套基线。按 Android `README.md:75-85` 的同名分支约定，验证改用该对象库已有的 `release/1.7.0` / `4f36969b7894df90af09fe9ae3a2797c8cd117ed`，嵌套字符串仓库严格采用此提交记录的 `313160d89cd6985e9bc7ef3d0a976da233feaa25`。
- 实测复制 Android 并从上述 Git 对象库按固定提交导出同名分支的 Shared 到隔离目录；仅在隔离 Android 工程以 `-PugreenHomeSharedPath=<隔离 Shared 路径>` 覆盖路径。不直接在 iOS Shared checkout 内执行构建，不修改 Android 原配置，不 checkout/reset 原 Shared。确认资源路径和 Composite Build 均使用此替换值。
- 分别记录“Android 原配置的缺失路径”“早期误用不同分支的失败”和“同名分支固定提交的集成验证”。同名分支验证即使通过，也不证明原缺失路径已修好，或任意同名分支提交均兼容。早期不同分支的 `:domain-product` 缺失不作为正确配套分支的当前阻断。未 fetch 或更新主工程；本地远端跟踪引用不冒充服务端最新状态。
- 共用内容去重：对照 iOS 现状笔记的源码快照，核实仍适用后通过相对链接引用共享模块职责、通用实现和已有说明，不重复展开。Android 文档保留 Android source set、依赖替换、平台实现、宿主调用/状态边界、版本差异及本轮实际构建/测试证据；历史 iOS 测试通过记录不能代替 Android 验证。

- 声明依赖与运行时调用分开记录；目录存在、依赖声明或测试文件数量不等于线上可达或执行通过。
