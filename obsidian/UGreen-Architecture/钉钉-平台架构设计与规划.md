# **一、 建设背景与目标**

## **1\. 背景** 

随着业务从单一手机配件向NAS、音视频、智能家居等复杂IoT领域扩展，UGreen面临着多端（Android/iOS/Win/Mac/Web）开发维护成本高、IoT协议对接复杂、安全合规要求日益严格等挑战。

## **2\. 建设目标**
- **提效：** 通过跨平台技术（KMP/RN）和组件化市场，实现业务代码复用率提升 40% 以上。
- **安全：** 建立全链路 DevSecOps 体系，确保应用从编码到发布的全生命周期安全合规。
- **统一：** 构建统一的大前端技术底座，屏蔽底层OS差异和IoT协议复杂度，让业务开发聚焦于用户体验。

# **三、 重点建设内容**

根据架构图，我们将建设内容划分为三大核心板块：

## **1\. P0 统一研发底座（基础层 & SDK套件）** 

这是地基，决定了上层建筑的稳固性。
- **基础原子能力：** 统一封装网络请求、图片加载、日志系统、加密存储、多语言国际化等基础库。确保一套代码在多端行为一致。
- **IoT SDK 套件化：** 将复杂的蓝牙配网、Matter协议、固件升级（FOTA）、远程/近场控制封装为标准 SDK。业务方只需调用简单接口即可完成设备控制。
- **跨端容器建设：** 重点建设 ReactNative 容器，以及 HTML5 容器（用于动态化运营活动），以及 KMP技术（用于高性能要求UI设计）。

## **2\. P1 组件市场（Component Market）** 

这是核心资产库，旨在实现“积木式”开发。
- **业务组件化：** 将通用业务逻辑（如用户登录、支付收银台、设备分享、AI相册浏览）剥离成独立组件。
- **治理机制：** 建立组件的发布、版本管理、依赖分析和自动化测试机制。
- **目标：** 实现“一次开发，多端复用”，例如针对 NAS 的文件管理和智能家居的场景化联动功能。

## **3\. P0 DevSecOps 研发流水线** 

这是生产管道，强调自动化与安全。
- **IDE 增强：** 开发定制化的 IDE 插件，内置AI编码、代码规范检查、安全漏洞实时提示、快速生成模版代码。
- **安全左移：**
    - **开发态：** 代码静态扫描（SAST）。
    - **构建态：** 开源组件漏洞扫描（SCA）、证书安全管理。
    - **测试态：** 交互式扫描（IAST）、合规检测（隐私政策、权限申请）。
- **自动化发布：** 支持灰度发布、分阶段全量、强制升级策略以及基于黑白名单的精准推送。



# **四、 整体规划路线图**

建议分三个阶段落地，周期预计 12-18 个月。

## **阶段一：夯实基础，统一标准（0-6个月）**
- **目标：** 解决“乱”的问题，统一技术栈。
- **动作：**
    - 完成 Android/iOS的基础库（网络、图片、日志）统一封装与开源/内部发布。
    - 搭建基础 CI/CD 流水线，集成代码扫描工具。
    - 完成 IoT 核心 SDK（配网、控制）的抽取，剥离业务代码。
    - 确立 RN 为主力的跨端技术方案，并在非核心页面（如“关于我们”、“设置”）试运行。

## **阶段二：组件沉淀，平台赋能（6-12个月）**
- **目标：** 解决“慢”的问题，提升复用率。
- **动作：**
    - 上线“组件市场”平台，强制推行核心业务（如登录、设备列表）组件化。
    - IoT 平台与移动端深度融合，实现 App 端无感接入新设备。
    - 完善 DevSecOps 中的安全卡点，实现“不安全不构建，不合规不上架”。
    - 建设运维平台，接入性能监控（APM）和崩溃分析。

## **阶段三：智能驱动，生态闭环（12-18个月）**
- **目标：** 解决“难”的问题，实现智能化运营。
- **动作：**
    - 全面推广跨端技术，核心业务页面复用率达到 60% 以上。
    - 引入 AI 能力（如智能场景推荐、相册语义搜索）到底层 SDK。
    - 完善埋点 SDK 与大数据分析平台，实现数据驱动的业务迭代。



# **五、 落地策略与保障**

## **1\. 技术演进策略：绞杀者模式**
- 不要试图重写所有旧代码。新业务强制使用新架构和组件；旧业务在迭代维护中逐步剥离功能，替换为新组件，最终完成替换。

## **2\. 组织架构适配：BP机制**
- 设立“大前端架构组”，负责平台、SDK和组件市场的建设。
- 设立“业务BP”，架构组成员派驻到耳机、NAS等业务线，负责推广新平台并收集反馈，避免平台建设与业务脱节。

## **3\. 质量与安全红线**
- **准入红线：** 所有上架组件市场的组件，必须通过单元测试覆盖率和静态安全扫描。
- **发布红线：** 任何包含高危漏洞（如硬编码密钥、严重隐私泄露）的包，CI/CD 流水线自动拦截，禁止打包。

## **4\. 文化建设**
- 推行“内部开源”文化，鼓励开发者贡献组件，并给予绩效奖励。
- 定期举办技术分享会，拉齐 Android、iOS、IoT 开发者的技术视野。
