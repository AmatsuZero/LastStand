## 当前事实快照（摸底）

### 运行时三栈并存
1. **Native Host**：设备列表、IPC 播放、配网、大部分设置（iOS UIKit / Android ViewBinding）
2. **KMP + CMP**：auth / env / root shell / home-management / OTA（进行中）；`device-biz` / thing-model 偏 Android，iOS umbrella 尚未导出
3. **RN**：设备设置面板；Android 生产路径较完整；iOS 在 feature 分支 / bundle stub，develop 未完整接线

### 动态下发
- **KMP**：编译期共享（framework/AAR），无热更新业务 UI 能力；无 js/wasm target
- **RN**：模块化 ZIP + manifest；远端 OTA 为 phase-1 scaffold；生产仍以包内嵌为主
- **结论倾向**：动态业务继续走 RN（或未来 Web），KMP 负责稳定域与可编译共享，不承担热发

### Toolkit 意图
把 KMP Feature 的 Role / 依赖方向 / 物理布局 / 验证变成可生成、可检查的契约（Role-first FeatureSpec v3）。解决架构一致性与骨架生产，**不**解决 RN、动态下发、设备 SDK 本身。
