# ECool 面试资料 Markdown 迁移设计

## 目标

将已登录的 `https://fe.ecool.fun/knowledge-learn` 中“面试资料”栏目转换为适用于当前 Hugo 站点的 Markdown page bundle，并按技术域建立可维护的目录、标签和分类。

本次范围是页面目录中现有的 10 个一级分类、191 个静态知识页：JavaScript 29 篇、CSS 27 篇、HTML 24 篇、React.js 21 篇、Vue.js 23 篇、计算机网络 20 篇、性能优化 4 篇、前端安全 12 篇、ES6 17 篇、工程化 14 篇。

## 约束

- 使用用户现有 Chrome 登录态访问会员内容，不读取或导出 Cookie、密码、本地存储或其他认证材料。
- 新文章默认 `draft = true`，不在本次任务中发布站点或推送远端。
- 忠实保留正文信息，但清理网页导航、会员标识、页内悬浮目录、关联面试题、站点页脚等非正文噪声。
- 不修改现有 `content/posts/interview/` 文章，不覆盖同名目录，不触碰与本次迁移无关的工作树变更。
- 先完成单篇样例并验证，再开始全量转换。

## 目录结构

新增独立来源层，避免会员资料与仓库原有原创内容混淆：

```text
content/posts/interview/ecool/
├── _index.md
├── javascript/
├── css/
├── html/
├── react/
├── vue/
├── network/
├── performance/
├── security/
├── es6/
└── engineering/
```

每个一级分类包含 `_index.md`，每个知识页采用 `<category>/<slug>/index.md` 的 Hugo page bundle 结构。Slug 优先由页面标题生成，统一转为小写英文或稳定的拼音/ASCII 形式；发生冲突时追加短标识，禁止覆盖既有页面。

## Frontmatter 与分类映射

文章 frontmatter 使用仓库现有 TOML 格式：

```toml
+++
title = "数据类型"
date = '2024-10-01T00:00:00+08:00'
lastmod = '2025-07-16T00:00:00+08:00'
draft = true
weight = 1
tags = ["面试", "前端", "JavaScript", "数据类型", "ecool"]
categories = ["前端开发", "面试"]
source = "https://fe.ecool.fun/knowledge-learn"
+++
```

映射规则：

| HTML | `html` | `前端开发`, `面试` | `HTML`, `面试`, `前端`, `ecool` |

## 内容转换

保留：

- 正文标题层级、段落、列表、引用和强调格式。
- 代码块、行内代码与可识别的语言标记。
- 表格及其表头、单元格内容。
- 正文中的有效外链。
- 页面创建时间和最近更新时间，分别映射为 `date` 与 `lastmod`。
- 对理解正文必要的图片，下载到文章 page bundle 并改为相对路径。

清理：

- 顶部导航、搜索框、用户头像和会员入口。
- 左侧知识树、VIP 图标、难度评分控件和页内悬浮目录。
- “预览”占位、无法取得的装饰图片和纯视觉图标。
- “关联面试题”区域及站点页脚。
- 重复的文章标题和转换器产生的空节点。

转换后执行基础 Markdown 规范化：标题从 `##` 正文层级开始、代码围栏闭合、表格列数一致、相对图片路径可解析、文件末尾保留单个换行。

## 提取流程

1. 从当前知识树读取分类、知识点标题与稳定页面标识，生成清单。
2. 选择 JavaScript / 数据类型作为样例，读取正文容器并转换为 Markdown。
3. 写入样例 page bundle，检查 frontmatter、正文结构、代码块、链接和图片。
4. 运行 Hugo 构建验证；样例不通过时先修正转换规则。
5. 按来源顺序逐页读取并转换，记录成功、跳过和失败项，支持中断后继续。
6. 生成来源栏目与十个分类的 `_index.md`。
7. 对 191 篇清单做数量、标题、目录、frontmatter 和非空正文核对。
8. 运行最终 Hugo 构建，并由独立验证通道复核迁移结果。

## 错误处理

- 登录失效、验证码或会员访问受阻时立即暂停，保留清单和已完成文件，等待用户恢复登录。
- 页面切换后必须校验正文标题与目标知识点一致，避免异步渲染导致内容错配。
- 单页转换失败时记录原因并继续后续页面；最终验收要求失败清单为空。
- 图片下载失败时保留正文并记录缺失资产；不得留下指向临时地址或本机绝对路径的引用。
- 已存在目标文件时默认跳过并报告，除非确认它是本次未完成的可恢复输出。

## 验收标准

- 清单包含 10 个分类、191 篇知识页，且每一项都对应唯一 page bundle。
- 所有文章包含合法 TOML frontmatter，`draft = true`，分类、标签、顺序和来源字段符合映射规则。
- 所有正文非空，没有站点导航、VIP 标识、页脚或关联题目等噪声。
- 代码围栏、表格和本地资源引用通过自动检查。
- `hugo --minify --buildDrafts` 成功完成，不新增构建错误，并实际覆盖本次新增的草稿页面。
- 工作树中只出现本次设计、迁移工具和 `content/posts/interview/ecool/` 相关文件。

## 非目标

- 不抓取“刷题”Tab 或 `/topic/...` 下的独立题库。
- 不发布 GitHub Pages、不推送远端、不把 `draft` 改为 `false`。
- 不校正原站正文中的技术结论，也不对内容做摘要式重写。
